# NekoShelf 部署指南（0.5.0）

面向家用 NAS / 自建 Docker 的部署说明。目标：挂载现有媒体目录，只读索引，浏览器访问即可用。

> **一键部署包**：[`deploy/`](../deploy/)（compose + env + 安装/备份/恢复/升级/自检脚本 + 反代示例 + 上线清单），推荐直接用包里的材料。
> 完整环境变量见 `deploy/.env.example`（或 `docker/.env.example`）；接口见 `docs/api-contract.md`；使用说明见应用内「帮助」（`/help`）。

## 1. 前置条件

| 项 | 要求 |
| --- | --- |
| 架构 | amd64 / arm64（单镜像，内置 ffmpeg、7zip、libarchive、sharp） |
| Docker | 20.10+，Compose v2（NAS 应用商店的 Docker 即可） |
| 内存 | 仅浏览 2GB 起；10 万文件扫描/多路转码建议 4–8GB |
| 磁盘 | `/config` 建议 ≥1GB（DB+备份），`/cache` 建议按库大小留 5–20GB，可随时清空 |
| 权限 | 容器进程 UID/GID（默认 1000:1000）需对 `/config`、`/cache` 可写，对 `/data` 可读 |

## 2. 部署（Compose，推荐）

```bash
git clone <你的仓库>/NekoShelf && cd NekoShelf/docker
cp .env.example .env
# 编辑 .env：MEDIA_DIR / CONFIG_DIR / CACHE_DIR / PUID / PGID / HTTP_PORT
docker compose -f docker-compose.prod.yml up -d
docker compose -f docker-compose.prod.yml ps        # 等 STATUS 出现 (healthy)
```

然后浏览器打开 `http://NAS地址:8080`：

1. 首次自动跳 `/setup`：设管理员账号（≥8 位）→ 添加媒体库（根路径填**容器内**路径，如 `/data`）→ 可选扫描；
2. 登录后进书库，等扫描完成；
3. 顶栏「帮助」有完整使用手册（登录页/初始化向导里也能直接点进来）。

### 或直接 docker run

```bash
docker run -d --name nekoshelf --restart unless-stopped \
  -p 8080:8080 \
  -e PUID=1000 -e PGID=1000 -e TZ=Asia/Shanghai \
  -e DATA_MODE=readonly \
  -v /volume1/comics:/data:ro \
  -v /volume1/docker/nekoshelf/config:/config \
  -v /volume1/docker/nekoshelf/cache:/cache \
  nekoshelf:0.5.0
```

## 3. NAS 平台要点

### 飞牛 fnOS（x86，N100/核显）

- Docker 应用（App Center）→ 新增容器或 Compose 导入 `docker-compose.prod.yml`。
- 卷映射到 `/vol1/1000/...`；PUID=1000 通常与桌面登录用户一致（`id` 确认）。
- 硬件转码：给容器加 `--device=/dev/dri`，`HWACCEL=qsv`；无核显用 `none`。
- 应用中心若要打包 `.fpk`：把镜像 `docker save` 后随包分发，端口 8080，数据卷映射同上。

### 群晖 DSM 7.2+

- Container Manager → 项目 → 新建，粘贴 `docker-compose.prod.yml`，或「导入 → 添加」镜像后手动配卷。
- 权限：`sudo id 你的用户` 看 UID（常见 1026）；PUID/PGID 用它；或先 `chown -R 1000 /volume1/docker/nekoshelf`。
- ARM 机型（DS223/DS124 等）：`HWACCEL=none`、`MAX_TRANSCODE=1`（软解仅 720p 一路），其余功能不受影响。
- 端口冲突：DSM 默认占用 8080（部分套件），改 `.env` 的 `HTTP_PORT` 为 18080 等。

## 4. 反向代理与 HTTPS

**同源浏览器访问**用 8080 即可，不配 Nginx 也能用。要域名 + HTTPS 时：

- 让反代只代理到 `nekoshelf:8080`，**开启 WebSocket/Upgrade**（扫描进度、任务轮询走普通 HTTP，但长连接升级头要透传）。
- 上传/响应体不大，但视频 Range 需要透传 `Range`/`Accept-Ranges`，不要缓冲整段。
- **以 HTTPS 前置反代为准**，容器内不处理 TLS。

nginx 片段：

```nginx
map $http_upgrade $connection_upgrade { default upgrade; '' close; }

server {
  listen 443 ssl http2;
  server_name nekoshelf.example.com;
  ssl_certificate     /etc/nginx/certs/fullchain.pem;
  ssl_certificate_key /etc/nginx/certs/privkey.pem;

  client_max_body_size 8m;
  proxy_read_timeout 300s;

  location / {
    proxy_pass http://127.0.0.1:8080;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection $connection_upgrade;
    proxy_buffering off;          # 视频 Range 直通
  }
}
```

Caddy 一行版：`nekoshelf.example.com { reverse_proxy 127.0.0.1:8080 }`。
群晖「反向代理」GUI 同样：来源 = 域名 443，目的地 = 127.0.0.1:8080，勾选 WebSocket。

> 反代后面部署时，客户端/第三方 App 要跨域访问才需要 `CORS_ORIGINS`；浏览器同源不需要。

## 5. 安全加固清单（上线默认值就是保守的）

- [ ] `DATA_MODE=readonly`（默认）；确认不需要整理才不开 writeback
- [ ] `ENABLE_SCRAPER=false`、`ENABLE_LLM_SEARCH=false`（默认关闭；确需时再开，并在设置页配凭据）
- [ ] 只映射必要端口；不要把 8080 直接暴露公网（走 VPN/Tailscale 或带认证的反代）
- [ ] `/config` 只在本地磁盘卷；不要把 `nekoshelf.db` 放 SMB/NFS（程序会拒绝启动）
- [ ] `/data` 保持 `:ro`；开启整理时再改 `:rw`，且先 dry-run 预览
- [ ] 首次初始化后立即在设置页设强密码；公网访问务必 HTTPS
- [ ] 定期点「立即备份」，或用宿主计划任务拷走 `/config/backups/*.db`
- [ ] 日志：默认 info；排查后再降回，`docker logs nekoshelf`（已限 10MB×3 轮转）

## 6. 升级与回滚

```bash
docker compose -f docker-compose.prod.yml pull   # 镜像有更新时
docker compose -f docker-compose.prod.yml up -d
```

- 启动时自动做幂等迁移（`PRAGMA user_version`）；**降级不保证**，升级前先备份。
- 回滚：停容器 → 用升级前的 `/config/backups/*.db` 覆盖 `nekoshelf.db`（同时删 `-wal`/`-shm`）→ 起旧镜像。

## 7. 备份与恢复

- 应用内（登录后）：设置 → 备份与维护 → 立即备份；写入 `/config/backups/nekoshelf-<时间>-<版本>.db`（`VACUUM INTO`，一致性快照）。
- 恢复：见应用内「帮助 → 备份与恢复」或 README「发布与备份」。
- 建议：NAS 计划任务每天 `rsync` 一次 `/config`（DB + backups + journal）到另一块盘。

## 8. 验收清单（部署后 5 分钟自检）

- [ ] `curl -s http://NAS:8080/healthz` 返回 `{"ok":true,...}`（页面能打开即已通过）
- [ ] `/setup` 完成初始化，登录成功；顶栏能进「帮助」
- [ ] 添加媒体库 → 扫描 → 任务页显示 `done`，书库出现作品，封面正常
- [ ] 打开一部作品阅读，翻页、进度保存（刷新后还在）
- [ ] 手机浏览器打开同一地址，布局自适应、可点击翻页
- [ ] 设置页：交互模式切换、AI/E-H 开关默认关闭（容器未设 env 时显示「不可用」提示）
- [ ] 点击「立即备份」，`/config/backups` 出现快照
- [ ] 对照「帮助 → 常见问题」逐条排除：权限、端口、封面、乱码

## 9. 常见故障

| 现象 | 处理 |
| --- | --- |
| 容器反复重启 | `docker logs nekoshelf`；多为 `/config` 无写权限（PUID/PGID 不符）或 DB 放在 SMB 上 |
| 页面 502 / 白屏 | 反代未启动或端口错；看 `docker ps` 与 health |
| 扫描 0 个作品 | 根路径填了宿主机路径；应填容器内 `/data` 之类 |
| 封面空白 | 目录里没有图片或压缩包首页损坏；重扫；清 `/cache/thumbs` |
| 中文乱码 | 压缩包内文件名编码混杂（GBK/UTF-8），zip 已优先按 UTF-8 标志位读，必要时反馈样本 |
| 视频卡顿 | 直连优先；不支持才转码，`HWACCEL=qsv`（x86 核显）或降低 `MAX_TRANSCODE` |
| 端口被占 | 改 `.env` 的 `HTTP_PORT`，容器内部始终监听 8080 |
| 升级后打不开 | 先看迁移日志；确认是从旧版本升级而不是降级；必要时按备份回滚 |
